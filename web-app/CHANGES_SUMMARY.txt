สรุปสิ่งที่แก้ไข/เพิ่มเติมในโปรเจกต์ KKU Return
(สำหรับให้เพื่อนในทีมอ่านแล้วเข้าใจว่าเกิดอะไรขึ้นบ้าง)
=========================================================

หมวด A: ฟีเจอร์ที่เพิ่มใหม่ (ระบบค้นหา/กรอง)
---------------------------------------------

1) หน้าค้นหา (/search) - ItemController::search()
   - กรองได้ 7 แบบ: ชื่อสิ่งของ, หมวดหมู่, ประเภท(พบของ/ของหาย), สถานะ, สถานที่
     (มี autocomplete), รายละเอียด, ช่วงวันที่
   - ซ่อนผลลัพธ์จนกว่าจะกดปุ่มค้นหาจริง (ไม่โชว์ของทั้งหมดตั้งแต่เปิดหน้า)
   - มีข้อความ "กำลังค้นหา..." ระหว่างรอโหลด
   - แบ่งหน้าผลลัพธ์ 5 รายการ/หน้า (เขียนปุ่ม Previous/Next เอง ไม่ใช้ของ
     Laravel default เพราะหน้านี้ไม่ได้โหลด Tailwind)
   - มีประวัติการค้นหา (เก็บใน session ล่าสุด 5 รายการ) ลบได้ทั้งหมด/ทีละรายการ

2) หน้าแอดมิน (/admin) - AdminController::index()
   - เพิ่มตัวกรองให้ตารางโพสต์ทั้งหมด: สถานะ, หมวดหมู่, สถานที่, ชื่อผู้โพสต์,
     ช่วงวันที่ (เดิมมีแค่ประเภท+ชื่อสิ่งของ)

3) หน้าโปรไฟล์ (/settings/profile) - ProfileController::edit()
   - ส่วน "โพสต์ของฉัน" กรองได้เหมือนหน้าแอดมิน (เฉพาะโพสต์ของตัวเอง)

หมายเหตุเรื่องโค้ด: ItemController/AdminController/ProfileController แต่ละตัวมี
private function filter($query, $request) ของตัวเอง (ไม่ได้แชร์โค้ดกันผ่าน Model
scope เพราะคุยกันแล้วว่าอยากให้โค้ดอ่านง่าย ไม่อยากมี abstraction ซับซ้อน)


หมวด B: บั๊กที่เจอและแก้ไปแล้ว
-------------------------------

1) หน้า /posts/create error "Undefined variable $colors"
   สาเหตุ: ฟอร์ม create ก๊อปปี้มาจากฟอร์ม agency เดิม แต่ ItemController::create()
   ไม่เคยส่ง $colors ไปให้ view
   แก้: ภายหลังฟอร์ม create ถูกเขียนใหม่ทั้งหมด (ตัดช่องสี/ยี่ห้อออก) ไม่มีปัญหานี้
   อีกแล้ว

2) หน้าแรก (/) error 500 "Undefined variable $returnUnit"
   สาเหตุ: resources/views/partials/return-units.blade.php (เป็นแค่ fragment
   แผนที่ ถูก @include เข้าไปในหน้าอื่น) ดันมี @extends/@section('title',
   $returnUnit->name) ค้างอยู่หัวไฟล์ ซึ่งไม่มี $returnUnit ส่งมาให้ตอน include
   แก้: ลบ @extends/@section ที่ไม่จำเป็นออก เหลือแค่เนื้อหาแผนที่จริงๆ

3) หลายหน้าไม่มี intro (ข้อความต้อนรับ) ใต้หัวข้อ "KKU Return: lost and found"
   สาเหตุ: ไม่ได้ใส่ @section('intro') ไว้ (4 หน้า: location/return-unit,
   user/edit, user/forgot-password, user/register)
   แก้: เพิ่ม @section('intro') @include('partials.intro') @endsection ให้ครบ

4) หน้า /settings/profile error "Undefined variable $type"
   สาเหตุ: ส่วน "โพสต์ของฉัน" ก๊อปปี้ฟอร์มกรองมาจากหน้าแอดมิน แต่
   ProfileController::edit() ไม่เคยส่งตัวแปรกรอง (type/status/category/ฯลฯ)
   ไปให้ แถมฟอร์ม action ชี้ไป route('admin.index') ผิดหน้า และปุ่ม "ล้างตัวกรอง"
   ชี้ไป route('profile.index') ซึ่งไม่มีอยู่จริง
   แก้: เพิ่ม filter() ใน ProfileController, แก้ route ในฟอร์มให้ถูก, แก้ id ของ
   datalist สถานที่ที่สะกดไม่ตรงกับ input ด้วย

5) หน้า /dashboard (ตอนนั้นยังชื่อ dashboard) error RouteNotFoundException
   สาเหตุ: เมนูเขียน route('location.dashboard') ทั้งที่ route จริงชื่อ
   'dashboard' เฉยๆ ('location.dashboard' เป็นชื่อ "view" ไม่ใช่ชื่อ "route")
   แก้: แก้กลับเป็น route('dashboard')

6) Vite manifest not found (ตอนเปิดหน้าที่ใช้ Livewire/Flux)
   สาเหตุ: ยังไม่เคยรัน npm install / npm run build ในเครื่องนี้เลย
   แก้: รัน npm install && npm run build

7) หน้า /posts/create error "table items has no column named
   deposit_image_url" (และก่อนหน้านั้นเคยเจอปัญหาคอลัมน์ color/brand หายด้วย)
   สาเหตุ: มีไฟล์ migration ใหม่อยู่แล้วแต่ไม่เคยรัน php artisan migrate
   แก้: รัน migrate (ได้ migration ค้าง 3 ตัว: เพิ่ม deposit_image_url,
   ลบคอลัมน์/ตารางที่เลิกใช้แล้ว, เพิ่ม is_banned)
   ** ข้อคิด: ทุกครั้งที่ pull โค้ดใหม่จากเพื่อน ควรรัน php artisan migrate
   เช็คก่อนเปิดเว็บเสมอ เพราะ migration ใหม่ไม่ auto-run เอง **

8) หน้ารายละเอียดของ (/items/{id}) โชว์เบอร์โทร/ชื่อผู้แจ้งผิด
   สาเหตุ: ไปดึงเบอร์โทร/ชื่อจากบัญชีผู้ใช้ (finder_users.phone/fullname) แทนที่
   จะใช้ค่าที่กรอกจริงตอนโพสต์ (items.reporter_phone/reporter_name) ทำให้เห็น
   เบอร์คนละอันกับที่กรอกในฟอร์ม
   แก้: ใช้ reporter_phone/reporter_name ของโพสต์นั้นก่อน ถ้าไม่มีค่อย fallback
   ไปที่ข้อมูลบัญชี

9) status ไม่สม่ำเสมอ มี 'ได้รับของแล้ว' ปนกับ 'ได้รับคืนแล้ว' (ความหมายเดียวกัน
   แต่สะกดคนละแบบ) ทำให้สถิติ/ตัวกรองนับซ้ำซ้อนกัน
   แก้: รวมเป็น 'ได้รับคืนแล้ว' คำเดียว ทั่วทั้งระบบ (เหลือ 3 สถานะหลัก:
   ยังไม่พบเจ้าของ / รอแอดมินยืนยัน / ได้รับคืนแล้ว บวกสถานะพิเศษ
   'หลักฐานไม่ถูกต้อง' ไว้แจ้งตอนแอดมินปฏิเสธหลักฐานโดยเฉพาะ)

10) เบอร์โทรศัพท์ไม่ตรวจสอบรูปแบบ (กรอกอะไรก็ได้)
    แก้: เพิ่มเงื่อนไขรูปแบบเบอร์ไทย (ขึ้นต้นด้วย 0, 10 หลัก เช่น 081-234-5678)
    ทั้งฝั่งฟอร์ม (HTML pattern) และฝั่ง server (Laravel validation regex) ที่
    หน้า create และ edit โพสต์


หมวด C: ฟีเจอร์ที่ถอดออก
-------------------------

1) ระบบ "หน่วยงาน" (Agency) ทั้งหมด - ไม่ได้ใช้แล้ว
   ลบ: AgencyItemController, EnsureUserIsAgency middleware, resources/views/agency/
   ทั้งโฟลเดอร์, AgencyUserSeeder, route agency.* ทั้งหมด
   ผลข้างเคียงที่เจอและแก้ไปด้วย: หน้า "แจ้งของหาย" ของ user ทั่วไป
   (user/create.blade.php) ดันเอาฟอร์มของ agency มาใช้ผิดๆ (ชี้ไป
   route('agency.store') ซึ่งกำลังจะโดนลบ) เลยต้องกู้ฟอร์มเดิมที่ถูกต้องกลับมา
   จาก git history แทน รวมถึงลิงก์ในหน้าแรก (home.blade.php) ที่ชี้ไป
   agency.create ผิดด้วย


หมวด D: ทำแล้วแต่ยกเลิกไป (ตามที่ขอ)
-------------------------------------

1) เงื่อนไขอีเมลต้องเป็น @kkumail.com หรือ @kku.ac.th เท่านั้น
   - เพิ่มไปแล้วที่หน้าสมัครสมาชิก+แก้โปรไฟล์ (ทั้ง validation ฝั่ง server และ
     pattern ฝั่ง HTML) แต่ภายหลังขอให้ลบออก เลยเอาออกทั้งหมดแล้ว ตอนนี้สมัคร/
     แก้โปรไฟล์ด้วยอีเมลโดเมนไหนก็ได้เหมือนเดิม


สรุปภาพรวม: บั๊กส่วนใหญ่ที่เจอมาจาก 2 แพทเทิร์นซ้ำๆ คือ
  (1) ก๊อปปี้ฟอร์ม/โค้ดจากหน้าอื่นมาใช้ แต่ไม่ได้แก้ route/ตัวแปรให้ตรงกับ
      หน้าใหม่ และ
  (2) มี migration ใหม่ในโค้ดอยู่แล้วแต่ไม่เคยรัน php artisan migrate
  ถ้าช่วยกันเช็ค 2 จุดนี้ทุกครั้งที่ pull โค้ด น่าจะลดบั๊กแบบนี้ไปได้เยอะ
