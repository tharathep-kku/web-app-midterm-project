สรุปสิ่งที่แก้ไข/เพิ่มเติมในโปรเจกต์ KKU Return — อัปเดตล่าสุด
(สำหรับให้เพื่อนในทีมอ่านแล้วเข้าใจว่าเกิดอะไรขึ้นบ้าง)
=========================================================

หมวด A: ยุบรวมตาราง finder_users เข้ากับ users (งานใหญ่สุดของวันนี้)
---------------------------------------------------------------------

ปัญหาเดิม: ระบบมี 2 ตาราง (users = บัญชี login, finder_users = ข้อมูลคน/เบอร์โทร)
ผูกกันผ่าน users.finder_user_id แต่คนที่สมัครสมาชิกจริงผ่าน /register ไม่เคยถูก
สร้าง finder_users ให้เลย ทำให้คนสมัครใหม่ไม่มีเบอร์โทร ไม่เห็น "โพสต์ของฉัน"
เพราะเงื่อนไขเช็ค finder_user_id ไม่ผ่าน

แก้โดยยุบรวม 2 ตารางเป็น users ตารางเดียว:
- เพิ่มคอลัมน์ phone เข้า users โดยตรง (ตัด username ออกเพราะไม่มีหน้าไหนใช้)
- ย้าย items.user_id ให้ชี้ไป users.id แทน finder_users.id
- ลบตาราง finder_users และคอลัมน์ finder_user_id ทิ้ง
- ลบ Model FinderUser.php, เปลี่ยน Item::reporter() ให้ belongsTo(User::class) แทน
- รวม Seeder (FinderUserSeeder + LoginUserSeeder) เป็น UserSeeder ตัวเดียว
- แก้ 12 ไฟล์ที่อ้างอิง FinderUser/finder_user_id (Controller, Model, Blade)

** บั๊กร้ายแรงที่เจอระหว่างทำ (แก้ก่อนส่งงาน) **
เขียน migration ย้ายข้อมูลรอบแรกโดย update where user_id = เลขเก่า ไล่ทีละคน
แต่เลข id เก่า (1-10) กับใหม่ (2-11) ทับช่วงกัน ทำให้แถวที่เพิ่งอัปเดตไปโดนจับคู่
ซ้ำอีกรอบ ผลคือของทั้ง 16 ชิ้นไหลไปกองที่คนเดียวผิดคนหมด — มี backup database
ไว้ก่อนรัน เลย restore แล้วเขียนใหม่ให้ปลอดภัย (สร้างตาราง map ไว้ก่อน แล้วอัปเดต
ทีละแถวโดยอิง items.id เอง ไม่ match ด้วย user_id ที่กำลังเปลี่ยนค่า) รันซ้ำแล้ว
เช็คละเอียดว่าของกระจายถูกต้องตรงเจ้าของทุกคน


หมวด B: เพิ่มช่องกรอกเบอร์โทร/ชื่อจริงตอนสมัครสมาชิก
------------------------------------------------------

- resources/views/user/register.blade.php — เพิ่มช่อง "เบอร์โทรศัพท์" (บังคับกรอก)

- resources/views/user/profile.blade.php — เพิ่มช่องแก้เบอร์โทรในหน้าโปรไฟล์ด้วย


หมวด C: ย้าย CreateNewUser ออกจาก Fortify มาเป็น Controller ธรรมดา
---------------------------------------------------------------------

- ลบ app/Actions/Fortify/CreateNewUser.php (Fortify Action class แบบ advanced)
- สร้าง app/Http/Controllers/RegisterController.php แทน (create()/store() ธรรมดา
  แบบเดียวกับ ForgotPasswordController ที่มีอยู่แล้ว)
- config/fortify.php — ปิด Features::registration() กัน route ชนกัน
- app/Providers/FortifyServiceProvider.php — ตัดส่วนจัดการ registration ออก
- routes/settings.php — เพิ่ม route register/register.store เอง

หมายเหตุ: Fortify ยังเหลือ login/logout ที่ยังใช้งานจริงอยู่ ไม่ได้ลบทั้งหมด
(route password-confirm ที่มากับ Fortify ไม่มีหน้าไหนใช้เลย เป็น dead code
ทิ้งไว้ก็ไม่กระทบอะไร)


หมวด D: ระบบค้นหา/กรอง
-------------------------

1) หน้าค้นหา (/search) - ItemController::search()
   - กรองได้ 7 แบบ: ชื่อสิ่งของ, หมวดหมู่, ประเภท, สถานะ, สถานที่ (autocomplete),
     รายละเอียด, ช่วงวันที่ — ซ่อนผลลัพธ์จนกว่าจะกดค้นหาจริง, มีประวัติการค้นหา
     (เก็บใน session), แบ่งหน้า 5 รายการ/หน้า

2) หน้าแอดมิน (/admin) - AdminController::index()
   - เพิ่มตัวกรอง: สถานะ, หมวดหมู่, สถานที่, ชื่อผู้โพสต์, ช่วงวันที่

3) หน้าโปรไฟล์ (/settings/profile) - ProfileController::edit()
   - ส่วน "โพสต์ของฉัน" กรองได้เหมือนหน้าแอดมิน (เฉพาะโพสต์ของตัวเอง)

หมายเหตุเรื่องโค้ด: ทั้ง 3 Controller มี private function filter($query, $request)
ของตัวเอง แยกกันคนละไฟล์ (ไม่ใช้ Eloquent scope ร่วมกัน เพราะคุยกันแล้วว่าอยากให้
โค้ดอ่านง่าย ไม่มี abstraction ซับซ้อนเกินจำเป็น)


หมวด E: บั๊กที่เจอและแก้ไปวันนี้
----------------------------------

1) หน้าโปรไฟล์โชว์เบอร์โทร/ชื่อผู้แจ้งผิด (item.blade.php)
   สาเหตุ: ดึงจากบัญชีผู้ใช้ (reporter->phone) แทนที่จะใช้ค่าที่กรอกจริงตอนโพสต์
   (items.reporter_phone) แก้ให้ใช้ค่าของโพสต์นั้นก่อน ถ้าไม่มีค่อย fallback

2) แอดมินที่เคยโพสต์เอง ไม่เห็นโพสต์ตัวเองในหน้าโปรไฟล์ + colspan ผิด
   สาเหตุ: ProfileController เช็ค role==='user' ก่อนถึงจะโชว์โพสต์ (แอดมินโดนกัน
   ออก ทั้งที่โพสต์ของได้เหมือนกัน) แก้เป็นเช็คแค่มีบัญชีผูกอยู่ก็พอ และแก้
   colspan="8" เป็น "10" ให้ตรงจำนวนคอลัมน์จริง

3) หน้าแรกพัง 500 error (partials/return-units.blade.php)
   สาเหตุ: ไฟล์นี้เป็นแค่ fragment แผนที่ที่ถูก @include แต่ดันมี
   @extends/@section ค้างอยู่หัวไฟล์ อ้างตัวแปรที่ไม่มีใน scope แก้โดยลบ
   @extends/@section ที่ไม่จำเป็นออก

4) หลายหน้าไม่มี intro (ข้อความต้อนรับ) ใต้หัวข้อหลัก
   แก้เพิ่ม @section('intro') ให้ครบ 4 หน้าที่ขาด

5) Vite manifest not found / column ขาดหาย (deposit_image_url, color, brand ฯลฯ)
   สาเหตุซ้ำๆ: มีไฟล์ migration ใหม่อยู่แล้วแต่ไม่เคยรัน php artisan migrate
   (หรือยังไม่เคย npm install && npm run build) แก้โดยรันคำสั่งที่ขาดไป
   ** ข้อคิด: ทุกครั้งที่ pull โค้ดใหม่จากเพื่อน ควรรัน migrate เช็คก่อนเปิดเว็บ **

6) status ไม่สม่ำเสมอ ('ได้รับของแล้ว' ปนกับ 'ได้รับคืนแล้ว')
   แก้รวมเป็นคำเดียว 'ได้รับคืนแล้ว' ทั่วทั้งระบบ

7) ย้ายไฟล์ Blade หลายรอบ (location/dashboard, user/create, user/edit, user/item
   ฯลฯ) แล้วลืมแก้ view()/route ในไฟล์ Controller ให้ตรง แก้ตามทุกครั้งที่เจอ


หมวด F: ฟีเจอร์ที่เพิ่มเติม
------------------------------

- แสดง "รูปตอนฝากของ" (deposit_image_url) ในหน้ารายละเอียดของ (item.blade.php)
  ตรงส่วนจุดรับ-ส่งคืน (เดิมบันทึกไว้ใน DB แต่ไม่เคยมีหน้าไหนแสดงเลย)
- กำหนดรูปแบบเบอร์โทรศัพท์ (ขึ้นต้น 0, 10 หลัก) ทั้งฝั่งฟอร์มและฝั่ง server


หมวด G: ฟีเจอร์ที่ถอดออก
-------------------------

- ระบบ "หน่วยงาน" (Agency) ทั้งหมด (AgencyItemController, middleware, views,
  seeder, route) ไม่ได้ใช้แล้ว ลบออกพร้อมแก้ผลข้างเคียง (ฟอร์ม create ของ user
  ทั่วไปดันไปใช้ของ agency ผิด)


หมวด H: ทำแล้วแต่ยกเลิกไปตามที่ขอ
------------------------------------

- เงื่อนไขอีเมลต้องเป็น @kkumail.com/@kku.ac.th เท่านั้น — เพิ่มไปแล้วแต่ขอให้
  ลบออก ตอนนี้สมัคร/แก้โปรไฟล์ด้วยอีเมลโดเมนไหนก็ได้
- Eloquent scope (scopeFilter) สำหรับระบบกรอง — เขียนแบบ shared scope ไปก่อน
  แต่ขอให้เปลี่ยนเป็น private function แยกคนละไฟล์แทนเพราะอ่านง่ายกว่า


สรุปภาพรวม: บั๊กส่วนใหญ่ที่เจอมาจาก 3 แพทเทิร์นซ้ำๆ คือ
  (1) ก๊อปปี้ฟอร์ม/โค้ดจากหน้าอื่นมาใช้ แต่ไม่ได้แก้ route/ตัวแปรให้ตรงกับหน้าใหม่
  (2) มี migration ใหม่ในโค้ดอยู่แล้วแต่ไม่เคยรัน php artisan migrate
  (3) ย้าย/เปลี่ยนชื่อไฟล์ Blade แล้วลืมแก้ view() ใน Controller ให้ตรง
  ถ้าช่วยกันเช็ค 3 จุดนี้ทุกครั้งที่ pull โค้ด น่าจะลดบั๊กแบบนี้ไปได้เยอะ
